# SaveE 화면별 표기 수치 정리 — 홈 / 지출 상세내역 / 소비 리포트

---

## 1. 홈 화면 (HomePage.vue)

### ① 이번 달 총 지출
- **API**: `transactionApi.getSummary({ userId, yearMonth })`
- **백엔드 계산**: 해당 유저·해당 월의 `txn_type = 0`(지출) 거래 전체를 `SUM(amount)`
- **표기**: `summary.totalAmount` 그대로 출력
- **비고**: 카테고리가 없는 거래(월세/적금이체)도 포함된 "진짜 총 지출"

### ② 지난달 대비 (~덜/더 쓰는 중이에요)
- **API**: `transactionApi.getSummary()`를 이번 달·지난달 두 번 호출
- **계산**: `diff = 이번달 totalAmount - 지난달 totalAmount`
- **표기 분기**: `diff < 0` → "덜 쓰는 중이에요" / `diff > 0` → "더 썼어요" / `0` → "지난달과 똑같이 썼어요"

### ③ 카테고리별 지출 (목표 카테고리별 실제지출 vs 목표금액 막대)
- **API 2개 조합**:
  - `goalApi.getMyGoals(yearMonth)` → 이번 달 목표금액(targetAmount), 목표 설정한 카테고리 목록
  - `transactionApi.getList({ userId, yearMonth })` → 이번 달 전체 거래내역
- **계산**: 거래내역을 **프론트에서** `categoryId`별로 직접 합산(`spendMap`) → 목표 카테고리 각각에 실제지출(actualAmount) 매칭
- **막대 길이**: `min(actualAmount / targetAmount * 100, 100)%`
- **초과 시**: `actualAmount > targetAmount`면 텍스트/막대 색이 빨강(`#e8512b`)

### ④ 이번 달 예상 절약 가능 금액
- **API**: `goalApi.getExpectedSaving()`
- **백엔드 계산**: 카테고리별 `max(최근 2~3달 평균지출 - 이번달 목표금액, 0)`을 전부 더함 (마이데이터 미연결 시 0)
- **프론트 추가 보정** (`adjustedExpectedSaving`):
  ```
  overageThisMonth = Σ max(이번달 실제지출 - 목표금액, 0)   ← goalBudgets에서 계산
  최종 표기값 = max(expectedSaving - overageThisMonth, 0)
  ```
  → "평균 기반 예상치"에서 "이번 달 실제로 초과한 만큼"을 실시간으로 깎아내는 방식
- **부가 문구 분기**:
  - 목표 자체가 없음(`goalBudgets.length === 0`) → "절약 목표를 세워보세요"
  - 계산값이 0 → "조금만 아껴볼까요?"
  - 그 외(양수) → "적금으로 모아보세요"

### ⑤ 내 적금
- **API 2단계**:
  1. `savingsApi.getMySubscriptionId()` → 가입한 적금 ID (없으면 null)
  2. 있으면 `savingsApi.getSavingsStatus(id)` → 상품명(productName), 누적납입액(totalPrincipal)
- **미가입 시**: "가입한 적금이 없습니다" 문구만 표시

## 2. 지출 상세내역 (TransactionListPage.vue)

### ① 소비 구성 도넛차트 (Top5 + 나머지)
- **API**: `transactionApi.getSummary({ userId, yearMonth })`
- **백엔드 계산**: 카테고리별 지출 합계를 **금액 큰 순으로 정렬**해서 상위 5개(Top5)만 개별로, 나머지는 "나머지"로 합산
- **가운데 총 지출**: Top5+나머지를 다시 합친 `summary.totalAmount`

### ② 필터칩 순서
- **API**: `goalApi.getMyGoals(yearMonth)` → categoryId 목록
- **계산**: 목표로 설정한 카테고리를 필터칩 **맨 앞으로 정렬**, 나머지는 기본 순서(category_id 오름차순)

### ③ 날짜별 거래내역 리스트
- **API**: `transactionApi.getList({ userId, yearMonth, categoryId? })`
- **계산**: 받은 거래 배열을 `txn_date` 기준으로 그룹핑 → 그룹 내에서는 `txn_date` 내림차순, 동일 날짜는 `txn_id` 내림차순
- **초기 10건만 표시**: 프론트에서 날짜 그룹을 순회하며 누적 10건까지만 자르고, "더보기" 클릭 시 전체 표시

## 3. 소비 리포트 (ReportPage.vue)

**전부 `/api/report?userId=&yearMonth=` 하나의 API 응답**(`ReportServiceImpl.getReport()`)에서 나옴 — 아래는 그 안에서 각 필드가 어떻게 계산되는지.

### ① 현금흐름 — 전월잔액 / 수입 / 지출 / 이달잔액
```
전월잔액 = deposit_account 기준잔액(initialBalance) + 그 이전 달까지의 누적 순증감(balanceDeltaBefore)
수입     = SUM(amount) WHERE txn_type = 1(수입) AND 해당월
지출     = SUM(amount) WHERE txn_type = 0(지출) AND 해당월
이달잔액 = 전월잔액 + 수입 - 지출
```

### ② 목표 대비 절약액 (report.saveAmount)
- **연동**: `GoalService.findMine()`(A팀) + `TransactionMapper.getCategorySummary()`(본인 도메인)
- **계산**:
  ```
  Σ (목표금액 - 실제지출)   ← 카테고리별, 초과분(마이너스)도 그대로 합산
  ```
- **목표가 하나도 없는 달**: `null` 반환 → 프론트에서 "-" 표시
- **전월 대비 비교(saveDiff)**: 이번 달 API와 지난달 API를 각각 호출해서 `report.saveAmount` 차이 계산 (프론트에서)

### ③ 이번 달 적금 납입액 (report.savingPayment)
- **출처**: `SUBSCRIPTION`/`PAYMENT` 테이블 직접 조회 (C팀 Service 완성 전이라 `ReportMapper`에서 직접 SQL)
- **계산**: `SUM(PAYMENT.amount) WHERE 해당 유저의 SUBSCRIPTION AND 해당월`

### ④ 주차별 소비
- **계산 방식**: `CEIL((일 + 월시작요일 - 1) / 7)`로 몇 주차인지 산출 (일요일 시작 기준)
- **조건**: `category_id IS NOT NULL` — **월세/적금이체 같은 고정지출은 제외**
- **1주차/마지막주차 "(총 N일)" 표기**: 프론트에서 그 달의 요일 배치를 계산해서, 7일이 안 채워진 주차에만 표시
- **최댓값 강조**: 가장 지출 큰 주차만 노란 막대, 나머지는 회색

### ⑤ 요일별 소비
- **계산**: `DAYOFWEEK(txn_date)` 기준으로 월~일 그룹핑 후 합산
- **조건**: 주차별과 동일하게 `category_id IS NOT NULL`만 집계
- **최댓값 강조**: 동일 원리(제일 큰 요일만 노란 막대)

### ⑥ 연령별 비교 Top3 (report.topCategories)
- **연동**: `PeerStatService.compareCategories()`(본인이 만든 별도 도메인 재사용)
- **myAmount**: 이 유저의 이번 달 카테고리별 지출 중 상위 3개
- **peerAmount**: 유저 생년월일로 계산한 연령대 + 해당 카테고리로 `peer_stat` 테이블(신한은행 실측 통계 기반 더미) 조회
- **막대 길이 기준**: Top3 안에서 `myAmount`/`peerAmount` 중 **최댓값을 100%**로 잡고 상대 비교 (전체 지출 대비 비중이 아님)

### ⑦ 이달의 Tip (AI 요약, report.aiSummary)
- **1차**: `report_ai_summary` 테이블에 이번 달 캐시가 있으면 그대로 반환 (OpenAI 호출 안 함)
- **없으면**: OpenAI(`gpt-4o-mini`)에 수입/지출/Top3 비교 데이터를 프롬프트로 넣어서 생성 → 캐시 저장
- **새로고침 버튼**: 캐시 무시하고 강제 재생성, **10분에 1번**으로 제한 (`report_ai_summary.created_at` 기준 검사)
- **실패 시**: 고정 폴백 문구로 대체 (DB엔 저장 안 함 → 다음 요청 때 재시도)

## 참고 — 공통으로 반복되는 원칙

| 원칙 | 내용 |
|---|---|
| **NULL 카테고리 처리** | 월세/전세대출이자/적금이체는 `category_id = NULL`. 소비 분석(주차별/요일별/Top5/목표비교)에서는 전부 제외, **현금흐름(잔액 계산)에서는 포함** |
| **목표 없는 달** | `saveAmount`는 `null`(프론트 "-"), 목표 카테고리 관련 리스트는 빈 배열 |
| **캐싱 원칙** | AI 요약만 DB 캐싱 (비용 절감), 나머지는 매번 실시간 계산 |
